Changing this machine

1 · Edit on a branch

cd ~/nixcfg
git checkout -b my-change
vim modules/dev-tools.nix       # or: code .

New files must be git add-ed before Nix can see them — flakes only read files git tracks. Staging is enough; it needn't be committed.

2 · Try it — reverts on reboot

sudo NIX_CONFIG='extra-experimental-features = nix-command flakes' \
  nixos-rebuild test --flake .#pi

test is not a dry run — it fully activates, restarting services and reconfiguring the network. Its one guarantee is that a power cycle undoes it. That is the escape hatch when a change costs you the network or the ability to log in.

3 · Keep it — merge first, then switch

git checkout main && git merge my-change && git push
sudo NIX_CONFIG='extra-experimental-features = nix-command flakes' \
  nixos-rebuild switch --flake .#pi

switch also sets the boot default, so only main ever decides what this machine boots into. Full runbook: ~/nixcfg/docs/DEPLOY.md

Running software without installing it

You almost never need to edit the config to try a tool. Nothing below changes the system, and nothing survives past the command.

Drop into a shell that has it

nix shell nixpkgs#wireshark
# wireshark is now on PATH; type `exit` and it is gone

Run it once and be done

nix run nixpkgs#cowsay -- hello
nix run nixpkgs#ffmpeg -- -i in.mp4 out.webm

Everything after -- is passed to the program, not to nix.

Several tools at once

nix shell nixpkgs#jq nixpkgs#httpie nixpkgs#ripgrep

Find what provides a command

nix search nixpkgs ripgrep

Add a package to modules/dev-tools.nix only once you've decided you want it there permanently. Downloads linger in the store until nix-collect-garbage -d reclaims them.

Tailscale

Join the tailnet (once)

sudo tailscale up

Prints a URL to approve in a browser. The node key persists in /var/lib/tailscale across reboots and rebuilds, so this is not repeated.

Where am I?

tailscale status
tailscale ip -4

The tailscale0 interface is trusted by the firewall, so anything this host listens on is reachable from your other devices without opening a LAN port for it. A service bound to 127.0.0.1 is still local-only — bind it to 0.0.0.0 to reach it over the tailnet.

Audio & Bluetooth

Headphones reconnect on their own at login — a bluetooth-autoconnect user service connects any paired, trusted device that advertises an Audio Sink. When it doesn't, these are the fallbacks.

Reconnect by hand

bluetoothctl devices Paired          # find the address
bluetoothctl connect <MAC>

Did the autoconnect service run?

systemctl --user status bluetooth-autoconnect

It is a oneshot pulled in by graphical-session.target, so it fires once per login. Retries at 0, 2, 4 and 8 seconds, then gives up quietly — it always exits 0 so absent headphones can never fail your session.

Pair something new

bluetoothctl
power on
scan on
# put the device in pairing mode, wait for it to appear
pair <MAC>
trust <MAC>
connect <MAC>
scan off
exit

Don't skip trust. Without it the device is not eligible for autoconnect, and you will re-pair every session. Note that trust alone is not enough either — it lets bluez accept a connection, never start one. That is the whole reason the service above exists.

Which output is actually being used?

wpctl status                         # the * marks the default sink
wpctl set-default <id>               # switch to another
wpctl inspect @DEFAULT_AUDIO_SINK@

Sink IDs change on every reboot. Always re-read them from wpctl status rather than reusing a number you saw earlier — targeting a stale id fails silently or plays to the wrong device. Run wpctl status while something is playing and a Streams: section shows which app is on which sink.

Working outputs on this machine

Bluetooth headphonesPreferred. A2DP/AAC.
3.5 mm jackWorks. The fallback when nothing else is connected.
HDMI → XREAL glassesNo audio. The Peakdo HDMI-to-USB-C converter passes the audio EDID but does not carry the stream — confirmed on other hardware. Use the glasses for video and Bluetooth for sound.

If Bluetooth audio stutters

iw dev wlan0 link | grep freq

Should report ~5785 MHz. The Pi's BCM43455 shares one 2.4 GHz antenna between WiFi and Bluetooth, so if WiFi has dropped to a 2.4 GHz channel (2412–2472) the two are fighting for the same radio. That is the cause far more often than the headphones are.

Housekeeping — old generations

Every switch leaves a generation behind, and each one pins its whole closure in the nix store. They are what you roll back to, so they are worth keeping — until they aren't.

See what has accumulated

sudo nix-env --list-generations -p /nix/var/nix/profiles/system
df -h /

Collapse to just the running one

sudo nix-collect-garbage -d      # system profile
nix-collect-garbage -d           # your user profile (home-manager)
sudo /run/current-system/bin/switch-to-configuration boot

That third command is not optional. Deleting generations does not rewrite /boot/extlinux/extlinux.conf. Skip it and the U-Boot menu still lists entries pointing at store paths that no longer exist — pick one and it will not boot. switch-to-configuration boot regenerates the menu against what actually survives.

Know what you are giving up

Afterwards there are zero rollback targets. A bad switch stops meaning “reboot and pick an older entry” and starts meaning “put the SD card in another machine”. The next switch creates a second generation and restores the safety net, so the exposure is only the window in between — which is why this belongs after a switch you have logged into and used, never before one.

Or keep a margin instead

sudo nix-env --delete-generations 30d -p /nix/var/nix/profiles/system
sudo nix-collect-garbage
sudo /run/current-system/bin/switch-to-configuration boot

Keeps anything from the last 30 days rather than collapsing to one.

When something breaks

A `test` went wrong

sudo reboot        # reverts to the last `switch`ed generation

A `switch` went wrong, and there is no network

nixos-rebuild --rollback fails offline — it tries to fetch the flake registry first. Use these instead:

sudo nix-env --rollback -p /nix/var/nix/profiles/system
sudo /nix/var/nix/profiles/system/bin/switch-to-configuration switch

Or reboot and pick an older generation from the U-Boot / extlinux menu — interrupt the countdown to get the list.

Which generation am I actually running?

readlink -f /run/current-system
readlink -f /nix/var/nix/profiles/system

Equal → the last activation was a switch and will persist. Different → a test is active and disappears on reboot.
